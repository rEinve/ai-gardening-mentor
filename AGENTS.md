# Repository Guidelines

## Project Structure & Module Organization
- This directory is the AI Gardening Mentor prototype within IntelliTheme Studio.
- `src/` contains the web application frontend source code: `src/index.html`, `src/styles/m3-tokens.css`, and `src/styles/main.css`.
- `dist/` is the compiled static production output generated by `npm run build`.
- `Containerfile` and `Dockerfile` provide multi-stage OCI container definitions (development, builder, production).
- `podman-compose.yml` and `compose.yaml` provide container service definitions for Podman and Docker.
- `CONTAINER.md` details container orchestration, rootless Podman execution, and volume mounting.
- `scripts/` contains build, dev-server, and container management utilities (`podman-build.sh`, `podman-run.sh`, `podman-dev.sh`, `podman-stop.sh`).
- `docs/` defines product requirements, technical architecture, schema, app flows, and prompt specifications.

## Build, Test, and Development Commands
- Package Manager: `npm` (Node.js 20+ / 22+).
- `npm run build`: Compiles `src/` into `dist/` via `scripts/build.mjs`.
- `npm run dev`: Starts local zero-dependency development server at `http://localhost:4321`.
- `npm run container:build`: Builds rootless Podman production image `ai-gardening-mentor:latest`.
- `npm run container:run`: Runs production container on port `4321`.
- `npm run container:dev`: Starts development container with live volume mount (`-v .:/app:Z`).
- `npm run compose:up` / `npm run compose:down`: Manages services with Podman Compose.

## Coding Style & Architecture
- Read `../../STUDIO_ARCHITECTURE.md` before new UI work and follow the workspace operational protocol.
- Use canonical ThemeUI tokens for colors, spacing, typography, and radii. Compose layouts with `.section`, `.container`, `.grid-12`, `.stack`, `.row`, and `.cluster`.
- Use BEM names, Dart Sass `@use`/`@forward`, the 7-1 structure, and at most three nesting levels. Components own interior styling only.
- Avoid inline styles, Tailwind, hardcoded colors, and page-specific layout grids. No local formatter or indentation configuration is established.

## Testing Guidelines
- No automated test framework, naming convention, or coverage threshold is configured.
- For documentation changes, verify paths and consistency with the requirements. When implementation begins, define executable checks for authentication boundaries, offline synchronization, and image validation.

## Commit & Pull Request Guidelines
- Parent Git history uses concise conventional subjects, such as `feat: ...` and `feat(mosibot): ...`. Use a relevant scope for this prototype.
- PRs should describe the change, link relevant requirements or issues, and report validation results and blocked checks. Include screenshots for visual changes.
- Do not add AI-authored commits `Co-Authored-By` unless explicitly requested by the user
